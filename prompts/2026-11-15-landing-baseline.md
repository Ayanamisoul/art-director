# 2026-11-15 — лендинг кофейни, нулевой бейзлайн

**Модель:** qwen2.5:7b-instruct (Ollama, локально, RTX 4060)
**Задача:** сценарий 2 (генерация по описанию) — одностраничный лендинг
**Запуск:** через API Ollama напрямую (`/api/chat`), без системного промпта

## Промпт
> Сгенерируй одностраничный HTML-лендинг для кофейни «Утро» в Москве.
> Требования: тёмно-коричневая цветовая гамма, hero-блок с заголовком и кнопкой
> «Заказать», секция меню из 4 позиций с ценами, блок контактов внизу.
> Верни только готовый HTML-код с инлайн-стилями, без пояснений.

## Результат
- Полный валидный HTML, 2362 символа, 726 токенов за ~15 сек (~48 ток/сек).
- Структура выполнена: hero + кнопка, меню 4 позиции с ценами, контакты.
- Отрендеренный результат см. в чате/скриншоте от 15.11.

## Проблемы (что чинить промптом или кодом)
1. **Ответ обёрнут в ```html-заборы** — парсить/срезать кодом либо запретить в промпте.
2. **Внешняя картинка `via.placeholder.com`** — недопустимо (суверенитет, офлайн).
   Запретить внешние ресурсы в промпте; изображения — только загруженные пользователем.
3. **Опечатка «маккиацchio»** — смесь кириллицы/латиницы. Кандидат на проверку
   блоком валидации.
4. Просили «инлайн-стили», модель сделала `<style>`-блок — следование инструкциям среднее.

## Выводы
- 7B справляется со структурой, но без жёстких рамок качество «школьный сайт».
- Следующий шаг: системный промпт с правилами (без заборов, без внешних ресурсов,
  заданная палитра/шрифты, обязательные секции) — сравнить с этим бейзлайном.
- Скорость на 8 ГБ VRAM достаточная для интерактивной работы.

## Замеченный инфраструктурный баг
Через curl на Windows русский текст уходит в битой кодировке → модель отвечает
по-китайски. Тестировать API через Python (`urllib`/`requests`), не через curl.
В Open WebUI один раз пришёл пустой ответ — повтор не воспроизвёлся, следим.
