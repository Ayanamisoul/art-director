# Арт-директор

Учебный проект Московского Политеха для Актиона. Менеджер передаёт бриф, выбирает образец оформления и получает редактируемую презентацию PowerPoint или автономный HTML-лендинг. Приложение умеет работать с длинным текстом, разделами, таблицами и фотографиями. Оба формата можно экспортировать в PDF.

## Создать презентацию на сайте

1. Откройте главную страницу. В поле «О чём презентация?» введите тему своими словами или вставьте готовый текст. Можно сразу указать аудиторию и число слайдов.
2. Приложите свой шаблон PowerPoint или PDF. Без шаблона сайт использует базовое оформление. В поле **«Изображения для слайдов»** можно выбрать или перетащить несколько фотографий, схем или логотипов. При необходимости укажите в брифе, где разместить каждый файл.

   Чтобы использовать свой шрифт, в поле **«Шрифт презентации»** выберите одно статическое начертание TrueType (.ttf, до 16 МБ). Для русского текста выбирайте шрифт с кириллицей. Сервис измерит текст этим шрифтом и встроит его в PowerPoint. При последующих правках выбор сохранится. Если в файле шрифта запрещено встраивание для редактирования, форма предложит выбрать другой файл.
3. Нажмите **«Создать презентацию»**. Первый слайд появится прямо на главной странице. Листайте кнопками под слайдом или стрелками клавиатуры, когда фокус в области просмотра. Рядом можно скачать PowerPoint, открыть редактор или попросить правки в чате. Если серверу не удалось отрисовать слайды, файл всё равно можно скачать.

Например: «Объясни первокурсникам, как работает память компьютера. Сделай 8 слайдов, покажи один расчёт и закончи задачей с ответом». Писать подробный промпт необязательно. По короткой теме сервис самостоятельно подбирает план. Если судья оставил замечания, они появятся рядом с результатом.

Настройку сервера и ключа модели выполняет тот, кто запускает сайт. Посетителю нужен браузер. Раздел **«Чаты и лендинги»** открывает прежнее рабочее пространство для загрузки изображений, выбора профиля лендинга и работы с историей. Текущая установка использует общую библиотеку файлов и чатов и рассчитана на локальную работу или доверенную команду.

**Можно использовать своего агента.** Любой агент, который умеет вызывать инструменты MCP по локальному `stdio`, может собирать материалы через этот проект. Агент с доступом к HTTP может поручить задачу встроенному агенту через `POST /api/chat`. Выбор способа важен: веб-чат добавляет правила проекта, закрепляет выбранный шаблон и вызывает судью. При прямом вызове MCP за бриф, инструкции модели и смысловую проверку отвечает вызывающий агент.

Для лендинга откройте **«Чаты и лендинги»**, выберите формат **«Лендинг (сайт)»** и приложите TTF в поле **«Свой шрифт»**. Шрифт включается в скачиваемый HTML и работает при открытии страницы офлайн. Используйте шрифт, лицензия которого разрешает публикацию на сайте.

## Какой способ подключения выбрать

| Задача | Точка входа | Кто принимает решения |
|---|---|---|
| Получить PowerPoint из темы и файла | Главная страница, `POST /api/create-presentation` | Форма отправляет `brief` и необязательный файл `template` вместе. Агент, сборщик и судья готовят файл для скачивания |
| Создать лендинг или продолжить чат | Рабочее пространство `/workspace` | Встроенный агент готовит содержание, сборщик оформляет его, судья веб-чата проверяет сохранённый результат |
| Получить тот же процесс из другого приложения | `POST /api/chat` | Приложение передаёт бриф и настройки. Работают тот же агент, инструменты и судья |
| Использовать другую модель во встроенном чате | Настройки API в `.env` | Модель совместимого провайдера выполняет генерацию и отдельный запрос на проверку. Правила и сборщики остаются в проекте |
| Дать собственному агенту инструменты презентаций и лендингов | MCP-сервер `artifacts` по `stdio` | Внешний агент составляет структуру и обрабатывает ответы инструментов. Код проекта проверяет структуру и собирает файлы |
| Опробовать встроенный агент в терминале | `agent/main.py` | CLI вызывает тот же цикл инструментов. Смысловая проверка и история веб-сессий реализованы в веб-приложении |

## Установка и первый запуск

Команды ниже выполняются в PowerShell из корня репозитория. Рабочий стенд проверен на Windows с Python 3.14. Для предпросмотра слайдов и экспорта PPTX в PDF используется настольный Microsoft PowerPoint через COM. Экспорт HTML в PDF запускает Google Chrome по пути `C:\Program Files\Google\Chrome\Application\chrome.exe`.

1. Создайте виртуальное окружение и установите зависимости.

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\python.exe -m pip install fastapi uvicorn python-multipart "mcp==2.3.0" python-pptx Pillow PyMuPDF fonttools
   ```

2. Подключите текстовую модель по [инструкции ниже](#model-setup). Для стандартной конфигурации Z.ai достаточно указать свой API-ключ.

3. Запустите веб-приложение.

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn web:app --app-dir agent --host 127.0.0.1 --port 8000
   ```

   Откройте [веб-интерфейс](http://127.0.0.1:8000) или [интерактивное описание HTTP API](http://127.0.0.1:8000/docs). Для работы в терминале выполните `.\.venv\Scripts\python.exe agent\main.py`. В CLI доступны `/skill chat`, `/skill landing`, `/new` и `/exit`.

## Как подключить свою модель

Это разовая настройка для человека, который запускает сайт. Посетителю нужен только браузер. Можно подключить облачную или локально развёрнутую текстовую модель, если её API совместим с OpenAI Chat Completions и поддерживает вызов инструментов. Именно через инструменты агент сохраняет PPTX и HTML. Для сервиса с другим протоколом или способом авторизации понадобится совместимый шлюз либо адаптер клиента.

**1. Создайте локальный файл настроек.** В PowerShell откройте папку проекта, где лежит `README.md`, и выполните:

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

**2. Укажите модель и ключ.** Для Z.ai заполните в открытом файле строку `ZAI_API_KEY=ваш_ключ`. Адрес сервиса и имя модели уже заданы по умолчанию. Для Qwen Актиона или другого провайдера заполните все три строки. Значения ниже — образцы для замены. Имена переменных с префиксом `ZAI_` сохраняются для любого провайдера.

```dotenv
ZAI_BASE_URL=https://model.example/v1
ZAI_MODEL=идентификатор_модели
ZAI_API_KEY=ключ_доступа
```

- **Адрес** берётся из документации провайдера или у администратора сервера. Если полный адрес метода — `https://model.example/v1/chat/completions`, запишите только `https://model.example/v1`: приложение само добавляет окончание. Для локальной модели укажите адрес, доступный с компьютера, на котором работает «Арт-директор».
- **Идентификатор модели** — точное значение поля `model`, которое принимает сервер. Для Qwen Актиона попросите у администратора этот идентификатор, базовый адрес, способ получения токена и условия доступа к корпоративной сети. Также уточните, включена ли поддержка `tools` и `tool_calls`.
- **Ключ** передаётся в заголовке `Authorization: Bearer …`. В локальном `.env` он хранится открытым текстом. Git игнорирует этот файл; в репозитории опубликован пустой образец `.env.example`. Сохраните изменения в Блокноте. Строки настроек должны начинаться с имени переменной, без символа комментария `#`.

**3. Запустите или перезапустите сайт** командой из раздела «Установка и первый запуск». Настройки читаются при старте. Если после перезапуска приложение использует прежнюю модель, проверьте системные переменные окружения: они имеют приоритет над значениями в `.env`.

**4. Проверьте создание файла.** Откройте главную страницу и введите: «Сделай три слайда о планировании недели с одним примером». Дождитесь кнопки «Скачать PowerPoint» и откройте файл. Так вы проверите и соединение с моделью, и вызов инструмента сохранения. Если сервер отвечает `401` или `403`, проверьте ключ и права доступа. При `404` сверьте адрес метода и идентификатор модели. Если модель отвечает текстом, но файл не создаётся, проверьте поддержку вызовов инструментов у выбранной модели и в настройках её сервера.

## От брифа до готового файла

1. Загрузите шаблон в библиотеку шаблонов, а фотографии — в библиотеку изображений. Выберите формат и конкретный шаблон PPTX/PDF или профиль лендинга. При сравнении нескольких дизайнов выбирайте их явно: выбор «авто» зависит от доступных файлов.
2. Укажите аудиторию, цель, желаемый объём, обязательные разделы, числа и примеры. Для фотографий назовите файл и место размещения. Если текст нужно перенести дословно, укажите, какие части разрешено разносить на несколько слайдов.
3. Веб-чат дополняет системные инструкции текущими настройками, доступными файлами и сведениями о последнем материале в чате. Текст из образца служит исходным материалом. Задачу задаёт пользователь.
4. Модель составляет структуру и вызывает инструменты. При явно выбранном формате приложение ограничивает набор инструментов и передаёт зафиксированные настройки в вызов сохранения. За один цикл агент может выполнить до пяти раундов обращения к модели. Замечания сборщика возвращаются в диалог для исправления.
5. После подтверждённого сохранения веб-чат передаёт судье выдержку из результата. Презентацию можно открыть в редакторе, просмотреть и экспортировать. HTML открывается как обычная страница. Для точечной правки продолжите тот же чат и назовите конкретный слайд или раздел.

### Презентации, шаблоны и длинный текст

| Исходник | Как использовать |
|---|---|
| Пустой PPTX или новая тема по образцу | Передайте обычные слайды. Сборщик использует доступные макеты, геометрию, шрифты, палитру и элементы шаблона. Совпадение зависит от устройства исходного PowerPoint |
| Заполненный PPTX, требуется точечная замена | Вызовите `read_template`. Он вернёт номера слайдов и ID текстовых фигур. Передайте исходные слайды по порядку через `source_slide` и замены через `template_fields`. Пустой объект замен сохраняет исходный текст данного слайда |
| PDF как образец | Приложение анализирует страницы, текстовые области, оформление и повторяющиеся элементы, затем составляет новые слайды PowerPoint. Опция «Без фото из PDF» управляет фотографиями исходного макета. Фотографии для нового материала выбираются отдельно |
| Презентация без шаблона | Выберите соответствующий режим. Приложение использует базовое оформление |

У слайда есть роль `title`, `section`, `content` или `closing`. Содержание можно представить списком `bullets`, подразделами `subsections`, карточками `cards`, показателями `stats` или таблицей `table`. Поле `image` принимает имя изображения из библиотеки. При изменении существующей презентации агент сначала читает `get_presentation`, меняет нужные поля и сохраняет **весь список слайдов** под прежним именем.

Правила задаются на двух уровнях. Системный промпт рекомендует одну мысль на слайд, 3–5 коротких пунктов, отдельные разделители крупных модулей и фотографии по просьбе пользователя. Затем код нормализует структуру и применяет ограничения.

| Что проверяет сборщик | Правило |
|---|---|
| Обычный список | До 6 основных пунктов, до 140 символов на пункт. До 4 подпунктов по 100 символов. Всего до 8 элементов списка с учётом вложенности |
| Заголовок | Основной заголовок до 110 символов. У титула, разделителя и финала заголовок до 70, подзаголовок до 90 |
| Карточки и показатели | Для сравнения промпт предлагает 2–4 карточки, для числовых выводов — 1–3 показателя. Длинные карточки могут стать самостоятельными слайдами |
| Таблица | 2–5 колонок, в каждой строке столько же ячеек, сколько заголовков. Таблица получает своё место на отдельном слайде. Длинная таблица делится на части максимум по 6 строк данных |
| Очень большой блок | Для текстового блока из пунктов, карточек и показателей и отдельно для таблицы действует ограничение в 8 000 символов. При превышении сборщик просит разделить материал. Бриф целиком может быть длиннее |

Восемь элементов списка могут занимать больше восьми визуальных строк. Сборщик отдельно измеряет текст по шрифту и доступной площади, учитывает переносы, отступы и место для картинки. Он подбирает кегль в пределах макета и при необходимости добавляет слайд-продолжение. Поэтому первоначальные 18 элементов структуры могут дать больше 18 страниц. Для жёсткого лимита указывайте **число слайдов в готовом PPTX** и какие подробности можно сократить.

### Лендинги

Страница собирается из заголовка `title`, вводного абзаца `lead` и разделов `sections`. У каждого раздела есть заголовок и при необходимости текст, список `items` и вложенные `subsections`. Из разделов формируется навигация. Параметр `cta` задаёт текст кнопки перехода к первому разделу, `brand` — подпись бренда, `image` — фотографию на первом экране.

Доступны три встроенных профиля: `glavbuh` («Главбух Нейро»), `school` («Высшая школа Юрист компании») и `law` («Нейропомощник юриста»), а также **примеры оформления от пользователя**. Загрузите HTML-страницу в разделе «Чаты и лендинги» (кнопка загрузки принимает `.html`) или через `POST /api/landing/examples` — модель один раз прочитает правила оформления примера (фон, шапку и подвал, типографику, отступы, кнопки, рамки фотографий) и составит CSS-профиль под структуру проекта; код проверит ответ и закэширует его. Дальнейшие сборки детерминированы. При недоступной модели стиль собирается упрощённо из палитры и шрифтов примера. Пример должен содержать стили внутри файла (`<style>`, `style=`) — страница, сохранённая «с папкой» с внешними CSS, получит упрощённый стиль. Загруженный пример выбирается в поле «Образец лендинга» или передаётся именем файла в `profile` инструмента `save_landing`; в режиме «авто» берётся самый свежий пример, а без примеров — встроенный профиль. Вёрстка и адаптивные стили встроенных профилей хранятся в проекте. При структурированной генерации фотография и используемые локальные ресурсы встраиваются в HTML. Для редактирования агент читает сохранённый бриф через `get_landing` и повторно вызывает `save_landing`; копия CSS примера хранится рядом с файлом, поэтому лендинг пересобирается даже после удаления примера. Произвольный HTML сохраняется отдельным инструментом `save_html`, доступным внешним MCP-клиентам.

## Как работает судья

После сохранения через главную форму или веб-чат приложение делает **отдельный запрос к той же настроенной модели**. Судья получает исходную просьбу и сведения из сохранённого файла. Он сверяет тему, явно запрошенные элементы и противоречия с брифом. В ответе HTTP поле `validation` содержит `ok`, `issues` и `raw`.

- Для презентации приложение открывает готовый PPTX и извлекает число слайдов, имя шаблона, текст фигур и ячеек таблиц. На один слайд в сводку попадает до 450 символов, на всю сводку — до 5 000.
- Для лендинга передаются профиль и до 3 500 символов видимого текста. На длинной странице судья может не увидеть последние разделы.
- Если судья нашёл несоответствия, веб-чат передаёт агенту до пяти замечаний, один раз запускает цикл исправления и повторно проверяет сохранённый результат. Один раунд исправления может включать несколько вызовов инструментов.
- Если сервис проверки недоступен или ответ невозможно разобрать ожидаемым образом, приложение может вернуть `ok: true` и диагностическое значение в `raw`. Для контроля смотрите оба поля и наличие файла в `saved`.
- Судья оценивает текстовую сводку. Шрифт, наложения и фактическую читаемость следует проверять в предпросмотре или экспортированном PDF. Внешнему агенту доступны те же сборщики и их проверки структуры; автоматический вызов этого судьи выполняется в обработчиках главной формы и веб-чата.

## Подключение собственного агента

**Через HTTP.** Запустите веб-приложение и отправьте запрос. Этот путь подходит, если нужны встроенные инструкции, история, выбор шаблона и судья. В следующем сообщении передайте полученный `session_id`, чтобы продолжить работу над тем же материалом.

```powershell
$brief = @{
    message = 'Сделай учебный лендинг по x86-64. Объясни, почему 4 + (−2) + 7 даёт 9. Включи программу и задачи с ответами.'
    output_format = 'landing'
    landing_profile = 'school'
} | ConvertTo-Json
$result = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/api/chat' -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($brief))
$result | Select-Object session_id, saved, validation, error
```

Для презентации используйте `output_format = 'presentation'` и поле `template` с точным именем загруженного файла. Имена можно получить через `GET /api/templates` и `GET /api/assets`. Оба ресурса принимают загрузку через `POST` с полем формы `file`. Список результатов доступен через `GET /api/files`, скачивание — через `/files/{имя_файла}`. Экспорт выполняют `POST /api/presentation/{имя}/pdf` и `POST /api/landing/{имя}/pdf`; здесь имя передаётся без расширения.

**Напрямую через MCP.** Зарегистрируйте локальный сервер в своём агенте. Укажите абсолютный путь к интерпретатору с установленными зависимостями и к скрипту. Ниже пример для клиентов с настройкой `mcpServers`; названия полей зависят от клиента. Замените `C:/Projects/art-director` своим путём.

```json
{
  "mcpServers": {
    "art-director": {
      "command": "C:/Projects/art-director/.venv/Scripts/python.exe",
      "args": ["C:/Projects/art-director/agent/mcp_servers/artifacts.py"]
    }
  }
}
```

Клиент сам запускает процесс и общается через стандартные потоки. Ключ модели принадлежит внешнему агенту. Самим сборщикам ключ Z.ai для создания файлов из готовой структуры не требуется. После подключения запросите список инструментов.

| Инструменты | Назначение |
|---|---|
| `list_templates`, `read_template` | Найти исходник и изучить его текст. Нумерация страниц начинается с 1, параметр `count` принимает значения от 1 до 20 |
| `list_images`, `list_artifacts` | Узнать имена загруженных фотографий и сохранённых результатов |
| `save_presentation`, `get_presentation` | Собрать редактируемый PPTX и прочитать сохранённую структуру |
| `save_landing`, `get_landing` | Собрать страницу по профилю и получить её бриф для изменений |
| `save_html`, `html_to_pdf` | Сохранить собственный HTML или экспортировать существующую страницу в PDF |

Для повторения подхода встроенного агента передайте своему агенту инструкции `ASSISTANT` из `agent/prompts.py`, текст брифа и явный выбор шаблона или профиля. Описание инструментов MCP содержит схемы их аргументов. Проверяйте результат вызова сохранения: он может содержать замечания, по которым агенту нужно изменить структуру и повторить вызов. Пример содержательного слайда для массива из трёх чисел:

```json
{
  "kind": "content",
  "title": "Как меняется сумма после каждого чтения",
  "table": {
    "headers": ["Индекс", "Условный адрес", "Элемент", "Сумма"],
    "rows": [[0, "0x1000", 4, 4], [1, "0x1004", -2, 2], [2, "0x1008", 7, 9]]
  }
}
```

## Как повторить последний практикум по ассемблеру

Контрольный пример «Маршрут одного числа: память, регистр, сумма» рассчитан на студента, который знает C и впервые открывает GDB. Бриф объёмом 9 122 знака запрашивал занятие на 50 минут. В нём заданы массив `[4, −2, 7]`, условный адрес второго элемента `0x1004`, три промежуточные суммы `4 → 2 → 9` и результат `0` при нулевой длине. Эти значения позволяют проверить, сохранил ли агент смысл при сокращении текста.

| Результат | Входные данные | Что было в последнем прогоне |
|---|---|---|
| `lab22_fonkor.pptx` | Шаблон `ФОНКОР 26 окт.pdf` | 18 слайдов. Фотографии на слайдах 3 и 4, таблица сумм на слайде 11 |
| `lab22_polytech.pptx` | Шаблон `Shablon_prezentatsii_MoscowPolytech.pptx` | 18 слайдов. Фотографии на слайдах 3 и 6, таблица сумм на слайде 11 |
| `lab22_school.html` | `school`, фото `asm_lab_processor.jpg` | 16 разделов и 23 подраздела |
| `lab22_glavbuh.html` | `glavbuh`, фото `asm_lab_board.jpg` | 9 разделов и 30 подразделов |

**Чтобы повторить генерацию**, возьмите исходники из локальных путей проекта: полный промпт — `data/artifacts/assembler_long_images_ru.md`, фотографии — `data/assets/asm_lab_processor.jpg` и `data/assets/asm_lab_board.jpg`, шаблоны — `data/templates/ФОНКОР 26 окт.pdf` и `data/templates/Shablon_prezentatsii_MoscowPolytech.pptx`. Каталог `data/` исключён из Git: на чистом клоне скопируйте эти файлы со своей машины. Загрузите исходники с теми же именами. Для каждого варианта откройте отдельный чат, выберите формат и оформление, вставьте полный бриф. Для обоих PPTX попросите разместить обе фотографии на разных содержательных слайдах. Для каждого лендинга укажите фотографию из таблицы. Задайте новые имена файлов, чтобы сохранить предыдущие результаты для сравнения.

**Чтобы повторить сборку согласованного материала**, используйте сохранённую структуру. Для презентации это соседний файл `data/artifacts/<имя>.json` с полями `title`, `subtitle`, `slides` и `theme`. Через MCP передайте первые три поля в `save_presentation`, новое `name`, имя шаблона из `theme.template` и сохранённый режим `theme.template_images`, если он указан. Если в теме задан `accent`, ему соответствует аргумент `accent_color`. Для лендинга вызовите `get_landing`, передайте возвращённые поля в `save_landing` и задайте новое имя. Используйте те же исходники и шрифты.

**Что можно гарантировать.** Новая генерация из текста снова обращается к модели. Даже при прежнем брифе могут измениться формулировки, разбиение на слайды, выбор таблиц и число попыток. Клиент не фиксирует `seed` и `temperature`. Сохранённая структура устраняет повторное сочинение текста. На внешний вид при пересборке всё ещё влияют путь сборки, доступные процессу шрифты, версии библиотек и PowerPoint. Для рассылки точно той же утверждённой версии используйте сохранённые PPTX, PDF и HTML.

После очистки репозитория проверка выполнялась в отдельной копии с двумя оригинальными шаблонами, двумя фотографиями и сохранёнными структурами. Новые тексты у модели для этой проверки не запрашивались.

## Проверка установки и результата

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe test_mcp.py
```

Первый запуск проверяет шаблоны PPTX и PDF, компоновку, обработку длинного текста, структуру лендингов и выбор оформления. Второй запускает настоящий MCP-сервер, запрашивает список инструментов, сохраняет тестовую HTML-страницу и экспортирует её в PDF. Файлы этого прогона появляются в `data/artifacts/`.

Для проверки новой модели начните с одного материала. Убедитесь, что в ответе `/api/chat` есть подтверждённый файл в `saved`, прочитайте `validation`, затем откройте сам результат. Для контрольного практикума проверьте число страниц, обе фотографии, адрес второго элемента, все три строки таблицы и ответ для пустого массива. Для лендинга проверьте разделы и подразделы, загрузку фотографии и переход по кнопке на узком и широком экране.

### Если результат отличается от ожиданий

| Наблюдение | Что проверить |
|---|---|
| Агент написал «готово», а файла нет | Посмотрите `error`, `tools` и `saved` в ответе чата. При подключении другой модели проверьте, вернула ли она вызов `save_presentation` или `save_landing` и принял ли его сборщик |
| Слайдов оказалось больше, чем в брифе | Откройте JSON рядом с PPTX и найдите слайды с пометкой «продолжение». Для сокращения попросите объединить близкие мысли или убрать второстепенные подробности, сохранив обязательные примеры |
| На слайде отсутствует фотография | Сверьте поле `image` с результатом `list_images`. Для PPTX файл ищется в библиотеке по имени; если его там нет, слайд может собраться без снимка |
| В готовом слайде изменились шрифт или переносы | Сравните исходный шаблон, способ запуска сборщика и доступные шрифты. Для проверки откройте сам PPTX в PowerPoint или экспортируйте его в PDF в том же окружении |
| PPTX сохранился, но нет превью или PDF | Проверьте, запускается ли настольный PowerPoint под той же учётной записью Windows. За конвертацию отвечает `scripts/pptx2pdf.ps1` |
| После подключения своего агента нет замечаний судьи | При прямом вызове MCP инструмент возвращает результат сборки. Для отдельной смысловой проверки используйте веб-чат через `/api/chat` или реализуйте её у вызывающего агента |
