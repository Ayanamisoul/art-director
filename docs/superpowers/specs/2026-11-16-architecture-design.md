# Реструктуризация «Арт-директора»: core-слой, тонкий MCP, PDF-экспорт, правила фото

Дата: 2026-11-16. Статус: одобрено партнёром в диалоге.

## Зачем
Логика приложения живёт в двух местах (MCP-инструменты и web.py) — расползается.
Фронт — монолит index.html (CSS+JS инлайном). Плюс четыре фичи от пользователя:
удаление картинок, «фото только по-пользовательски», экспорт в PDF, независимый
скролл панели.

## Verdict по MCP
MCP — требование заказчика и канал для CLI. **Оставляем как тонкий адаптер**:
рабочая логика не зависит от MCP, при необходимости адаптер выкидывается без
последствий.

## Архитектура
```
agent/
  core/            # рабочая логика без HTTP/MCP: decks, templates, assets,
                   # artifacts, sessions, previews
  mcp_servers/artifacts.py   # тонкий адаптер: инструменты -> core.*
  routers/         # FastAPI-роутеры -> core.* (sessions, templates, assets, files)
  web.py           # сборка app, static, lifespan
  static/          # style.css + app.js (фронт без фреймворков)
  pptx_builder.py  # низкоуровневая сборка pptx (не меняется)
```

## Фичи
- PDF-экспорт: POST /api/presentation/{name}/pdf (PowerPoint COM через
  scripts/pptx2pdf.ps1) -> data/artifacts/{name}.pdf; кнопка в превью чата
  и в редакторе.
- Фото: модель ставит image ТОЛЬКО при явной просьбе/загрузке (промпт);
  чужие фото из PDF-шаблонов вырезаются при растеризации (уже сделано,
  усилено: любые не-фоновые).
- Удаление: DELETE /api/session/{id} (есть), + DELETE /api/assets/{name}
  и кнопки 🗑 у картинок в панели.
- Скролл: body overflow hidden, каждая колонка листается сама.

## Подходы (рассмотренные)
- (а) Умеренный рефакторинг без смены стека — ВЫБРАН (риск/время до встречи).
- (б) Полный рефакторинг (Vue/React, БД) — отклонён: день работы, риск перед
  показом, заказчику не нужно.
- MCP убрать совсем — отклонено: требование заказчика.

## Не входит
Редактор editor.html остаётся монолитом (только добавлена PDF-кнопка).
