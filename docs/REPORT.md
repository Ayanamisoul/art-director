# Арт-директор — отчёт о работе

**Ссылка на репозиторий:** https://github.com/Ayanamisoul/art-director
**Локальный запуск:** `cd agent && py -m uvicorn web:app --port 8000` → http://localhost:8000
**Стек:** Python · FastAPI · python-pptx · PyMuPDF · PowerPoint COM · MCP. Приложение хранит файлы и собирает макеты локально. Стенд отправляет запросы модели и семантическому судье через настроенный API Z.ai.

## Работа по образцу

Оформление зависит от выбранного файла. В PPTX новые блоки используют тему мастера текущего слайда, фон, гарнитуры и доступные стили текстового поля. В PDF сборщик извлекает гарнитуры и расположение элементов из страниц, а цвета новых таблиц подбирает по фону и тексту соответствующей страницы. Образец «ФОНКОР» служит одним из вариантов оформления. Если в PDF текст превращён в изображение или имя шрифта скрыто, точное восстановление гарнитуры ограничено данными файла.

В примере `assembler_fonkor_layouts` по «ФОНКОР» короткая вводная и две карточки повторяют композицию страницы 2, вывод и три показателя в соседней колонке — страницы 9, а таблица с заголовками — страницы 16. Поле `table` принимает 2–5 заголовков в `headers` и строки в `rows`. Таблица редактируется по ячейкам в PowerPoint и в веб-редакторе. На продолжениях сборщик повторяет заголовки колонок.

- **Адаптация готового PPTX.** Загрузите исходную презентацию и попросите заменить конкретные данные. Инструмент `read_template` читает исходные страницы и их текстовые поля. В режиме точечной правки сборщик меняет указанные поля и сохраняет композицию, изображения и оформление остальных элементов. Тот же результат можно открыть в редакторе.
- **Новая презентация по PDF.** Выберите файл в поле «Шаблон слайдов». Сборщик использует позиции, размеры и цвета текста, фоновые заливки, характерные детали и подходящие страницы для содержательных слайдов. Если имя шрифта скрыто внутри PDF, сборщик подбирает локальную гарнитуру по метрикам. В «ФОНКОР 26 окт.pdf» это требуется для встроенных шрифтов Type 3.
- **Лендинг по образцу.** В формате «Лендинг» выберите «Главбух Нейро», «Высшая школа Юрист компании» или «Нейропомощник юриста». Модель передаёт заголовок, лид и разделы в `save_landing`. Локальный сборщик отвечает за сетку, палитру, заголовки, кнопки и мобильную версию. Для нового лендинга без указания образца базовым служит «Главбух Нейро». Лендинг хранит свой стиль и редактируемые данные внутри HTML. Кнопка «Скачать PDF» доступна в предпросмотре.
- **Шрифты лендингов.** У варианта школы Inter встроен в HTML с латиницей и кириллицей. «Главбух Нейро» использует установленный Lab Grotesque с запасным Arial. Юридический вариант использует системную гарнитуру, как опубликованный образец.

Образцы лендингов взяты со страниц [Главбух Нейро](https://about.1gl.ru/ai/), [Высшей школы Юрист компании](https://school.law.ru/neyro/) и [Нейропомощника юриста](https://neyro-law.ru/).

**Проверка 19 ноября 2026 года.** В браузере через чат созданы лендинг практикума и презентация из четырёх слайдов по загруженному «ФОНКОР 26 окт.pdf». После переоткрытия чата изменён заголовок второго слайда, затем в редакторе изменён текст карточки третьего. Обе правки проверены в экспортированном PDF. У лендинга проверены переход к программе на мобильном экране и отдельный PDF из двух страниц. Регрессионные проверки запускаются из корня проекта командой `py -m unittest discover -s tests -v`.

В контрольной презентации `practicum_text_images.pdf` материал из 2 508 знаков занимает восемь слайдов. Два абзаца по 508 и 488 знаков разнесены на соседние страницы с кеглем 22 пт. Короткие тезисы набраны 28 пт, карточки — 23 пт, текст рядом с иллюстрацией — 20 пт. В экспортированном PDF проверены полнота текста, границы страниц, наложения и пропорции фотографии 620 × 322.

Тот же бриф передан через чат с просьбой выделить главное и вставить иллюстрацию из библиотеки. В `praktikum_iz_brifa.pdf` получилось 11 слайдов. Сохранены обязанности преподавателя и администратора, порядок проверки тестовой заявки и условие про звонок и электронную почту. Для всех 11 страниц доступны превью из PowerPoint.

## Требования заказчика (Актион, учебный проект Московский Политех)
1. AI-агент: менеджер на естественном языке получает презентации и лендинги.
2. **MCP-сервер** — обязательное требование (Актион использует Qwen; должна быть возможность подключить любой LLM-клиент).
3. **Валидация результата**: код → LLM-судья → человек.
4. Экспорт в PDF.
5. Local-first: всё крутится на машине пользователя, без облаков.

## Что сделано

### Ядро агента
- Чат-цикл с инструментами: модель сама решает, когда сохранить презентацию/лендинг.
- Один бэкенд LLM — Z.ai · GLM 5.3 Flash (селектор моделей убран по решению пользователя).
- **MCP-сервер** — тонкий адаптер над `core/` (создание презентаций/лендингов, чтение ассетов). Приложение от MCP не зависит — можно подключить любой MCP-клиент.
- **Судья (semantic_check)** сверяет имя и содержимое сохранённого результата текущего хода с запросом. При замечаниях агент получает один дополнительный ход для исправления. Недоступность судьи не блокирует выдачу файла.
- **Проверка объёма.** Сборщик распределяет абзацы и подпункты по слайдам. Если модель предлагает поместить более 8 000 знаков основного материала в один блок, она получает запрос выделить темы и повторить сохранение.

### Сборка презентаций (.pptx)
- **Работа по скелету шаблона .pptx**: слайды шаблона сохраняют дизайн, подкладывается только наш контент. Позиционная раскладка: первый лист — титул, последний — финал, средние — контент; недостающие клонируются с дизайном.
- **Карта дизайна шаблона**: фирменный шрифт (layout → master → txStyles) и **детект логотипа** (растеризация, компактные кластеры в углах, отсев линий) с кэшем по mtime. Цифры/карточки/картинки не наезжают на лого и декор.
- **Размер основного текста.** Сборщик измеряет слова в гарнитуре слайда, учитывает поля, отступы и место для иллюстраций. Для новых тезисов и подписей нижний предел составляет 18 пт. Когда тексту тесно, сборщик переносит его на дополнительный слайд. Точечная замена в готовом PPTX сохраняет исходный кегль поля.
- **Богатые слайды**: подпункты (`{text, sub}`), крупные цифры (`stats`), рамки (`frame`), карточки-«окошки» (`cards` 2–4), линейка под заголовком (только однострочным и если у шаблона нет своего декора в этой зоне).
- **Иллюстрации.** Сборщик вписывает пользовательскую картинку целиком в выделенное поле, сохраняет пропорции, прозрачность и поворот фотографии по EXIF. Текст занимает соседнее поле.
- **Титульник**: перенос строк включён, ширина зоны нормализована, кегль подгоняется, ничего не обрезается.
- **Эмодзи** вырезаются из контента (и запрещены в промпте) и убраны из интерфейса.
- **PDF-шаблоны** принимаются через кнопку и перетаскивание. Декор и новый редактируемый текст формируются отдельными слоями.

### Интерфейс
- Веб-чат (FastAPI + vanilla JS): drag&drop и Ctrl+V файлов, статусы загрузки, превью результата настоящим рендером (PPTX→PDF→PNG), кнопки «Редактировать», «чат», «Скачать PDF».
- Выбор шаблона пользователем (селект + `.preferred`), «без фото из шаблона», формат результата (авто/презентация/лендинг).
- Панели: файлы, чаты (создание/удаление/восстановление по ссылке), картинки (миниатюры, удаление).
- Редактор презентаций (тексты слайдов) с PDF-экспортом.

### Прочее
- PDF-экспорт через PowerPoint COM (`scripts/pptx2pdf.ps1`).
- Превью-рендер любого артефакта, натуральная сортировка страниц.
- Чистый рефакторинг: `core/` (sessions/templates/assets/artifacts/decks/previews) + `routers/` + тонкий `web.py`, фронт разделён (style.css/app.js).
- Документация: `docs/architecture.md`, `docs/mcp-and-natural-language.md`, докстринги инструментов MCP.

## Что проверить (чек-лист перед показом)
1. Сервер: `py -m uvicorn web:app --port 8000` (порт 8000 бывает занят другими программами — проверять по содержимому страницы, не только по коду ответа).
2. Новая презентация по запросу с деталями (цифры + «карточками» + подпунктами) — модель должна применить embellishment уместно.
3. Слайды с картинками (загрузить своё изображение) — текст не должен наезжать на картинку и лого.
4. Плотный слайд (много материала) — шрифт ужмётся или модель разделит на два слайда.
5. Титульный лист — заголовок/подзаголовок целиком в зоне дизайна, ничего не обрезано.
6. Замена шаблона через селект — пересборка на другом шаблоне, лого/шрифт подхватятся.
7. PDF-экспорт из чата и редактора.
8. Редактирование: правка текста слайда не теряет новые поля (stats/cards).
9. Подключение внешнего MCP-клиента (`test_mcp.py`, докстринги в `agent/mcp_servers/`).

## Известные ограничения
- Детект лого — эвристика (плотные кластеры в углах): монохромный лого на пёстром фоне может быть не найден.
- Переносы зависят от доступной на компьютере гарнитуры. Сборщик использует метрики установленного шрифта и запас места. Предпросмотр сохранённой презентации показывает страницы, отрисованные PowerPoint.
- PDF-экспорт требует установленного PowerPoint; на машинах без него недоступен.
- У полностью растровых PDF недоступны исходные текстовые поля. Точечная замена по идентификаторам полей доступна для PPTX.
- Ролевая админка и загрузка отдельных файлов шрифтов из полного ТЗ остаются отдельными задачами.
